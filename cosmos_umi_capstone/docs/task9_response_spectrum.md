# Task 9: local response spectra across Bridge scenes and noise seeds

Task 9 probes the actual post-VAE first-frame condition of the validated Task 8 FP32
`G → D → E` runtime. It uses three eligible Bridge episodes in original TFRecord
order, two diffusion seeds per episode, and scene-specific fixed action chunk 0.
This is a conditional experiment: the official Bridge action adapter derives motion
from observed future poses. It is not control-only open-loop forecasting.

## Frozen design

- 32 orthonormal Gaussian training directions and eight independent orthonormal
  held-out directions in the runtime condition mask, generated by NumPy seed
  `20260923`. The same direction bank is reused across scenes if mask geometry
  matches.
- Central paired responses at `alpha=0.003`, plus independent half-step checks
  at `alpha=0.0015` for every direction. The input step is `alpha` times the
  masked RMS of the scene's baseline condition. There is no clamp or image
  quantization in the feedback path.
- Two exact-condition baselines bracket the 160 paired perturbation calls:
  `baseline_pre`, 32×2 training, 8×2 held-out, 40×2 half-step,
  `baseline_post` = 162 calls per scene/seed, all sequential in one runtime.
- Task 8's official action and prompt are fixed within a scene; seed 0 and seed
  1 are separate scans with their own matched initial noise. Denoiser action
  tokens and condition tokens are observed at all 30 steps.
- One baseline engineering smoke precedes the first formal stratum. The smoke
  is not included in its response matrix.

For each stratum, SVD is applied separately to the uncentered matrix of 32
central response columns. Separate matrices are formed for the generated
predicted latent, the FP32 re-encoded feedback condition latent, and the final
float RGB frame. No columns from different base scenes or noise seeds are pooled
into a single purported Jacobian. The eight held-out responses test whether a
truncated output subspace transfers to unseen input directions.

## Analysis and interpretation

The report gives squared-singular-value cumulative energy, `k90/k95/k99`,
entropy effective rank, and held-out projection residuals by rank. The formal
half-step check requires response above 10× the larger of measured baseline
repeat RMS and a heuristic FP32-scale floor; it also checks input direction,
derivative cosine, and derivative RMS change. Singular values below the
output-resolution/actual-step threshold are excluded from *resolved* rank and
energy; the raw spectrum and the fraction of raw energy excluded remain in the
report. This threshold is not a rigorous error bound for the full model.

A failed half-step check does not erase the measured finite-amplitude response
or justify changing `alpha` after seeing the data. A passing check is empirical
local-linearity evidence for the sampled directions, not a proof of Jacobian
existence. Even a sharply concentrated spectrum is a claim only about the
sampled input subspace and chosen output representation; rank is at most 32.

## Reproduction entry points

`umi_task9_bridge_preflight.py` extends the Task 8 generation-free Bridge
preflight with `--eligible-rank 0`, `1`, or `2`. Each report binds a 33-frame
window, official 10D action conversion/normalization, source metadata and
SHA256. The scene's `preflight_window.npz` and `task8_preflight.json` are passed
to `run_umi_task9_live.py` along with the verified Task 8 runtime snapshot,
official framework, checkpoint and VAE paths. The live launcher requires
`--release` and explicit `--seed 0` or `--seed 1`; omit `--release` to inspect
arguments without loading a model. Add `--smoke` only for one baseline call.
`--resume` is explicit and checks immutable code, model, VAE, data, directions,
configuration and sample hashes before skipping successful samples.

After a stratum completes, run `analyze_umi_task9_scan.py --scan-dir <run/scan>`.
Once all six analyses exist, pass their six scan directories separately to
`analyze_umi_task9_matrix.py --scan-dir ... --output-dir <new-dir>`; the matrix
collator refuses missing, duplicate or mismatched scene/seed identities and
does not perform a pooled SVD.

CPU tests: from `cosmos_umi_capstone/experiments`, run
`python -m unittest discover -p 'test_*.py' -q`.

Large model weights and raw float tensors stay on the server. Only source,
small reports, CSVs, figures and verified provenance belong in Git.
