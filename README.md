# MATH 4999 Capstone · 视频预测从第几帧开始偏离真实画面？

**在能逐帧做这项比较的那次测试里，预测视频与真实视频的差距第一次超过标准是在第 30 帧。** 我们想知道，在看真实后续画面之前，能把这个时间估得多准。给评分加上像素取值的限制后，方法仍把第 2 到第 80 帧都列为可能，还保留了“80 帧内一直没超过”的可能。

## 第 30 帧是怎么算出来的？

我们用同一个视频模型，给它起始画面和记录好的动作，让它生成后续画面。再把生成画面与同一时刻的真实画面逐帧对齐，将红、绿、蓝三个通道的像素值放在 0 到 1 的尺度上，计算每帧的均方根误差。误差**第一次大于 0.20**，就记下那一帧。等于 0.20 还在范围内。即使之后误差又降下来，首次超过的那一帧也照样记。我们观察 80 帧，把“80 帧内一直没超过”单独记为一种结果。

## 能把时间范围缩小多少？

实验用了 16 段来源视频，每段运行两次。5 段用于设计方法，5 段用于定下保留候选帧的评分门槛，最后用 6 段作回顾性检查。下表对应测试中唯一保留了前 48 帧生成画面、能按像素比较的那次运行。

| 方法 | 保留哪些帧？ | 还允许 80 帧内一直没超过？ |
| --- | --- | --- |
| 所有视频共用的规则 | 第 6–71 帧 | 是 |
| 按这次生成画面评分 | 第 2–80 帧 | 是 |
| 加入像素限制的两种评分方法 | 两种都是第 2–80 帧 | 是 |

三个按画面评分的方法都包含真实答案第 30 帧。加入像素限制后，**评分门槛从 42.55 降到 33.82，下降约 20.52%**。这两个数用于筛选候选帧，衡量画面误差的标准始终是 0.20。这次门槛下降后，多排除的候选帧是 **0 个**。

另外 11 次测试运行有逐帧误差记录，但缺少这项比较所需的生成画面，所以每次都保留了全部 81 种结果。按来源视频看，6 段的两次运行都包含真实答案，同时做到两次都包含答案、范围又比公共规则更窄的是 **0 段**。
